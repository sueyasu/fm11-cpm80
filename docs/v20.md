# NEC V20 CP/M-80 target

The V20 runs the common 8080 CCP, BDOS and CBIOS in its 8080 emulation
mode, with native I/O via CALLN. No optional Z80 card is needed.
The default 6809+Z80 and experimental 8088+Z80 targets remain unchanged.

## Build

Requires NASM, asm8080, Python 3 and GNU make 4.3+ (grouped image targets).
From the repository root:

```sh
make imagev20
make test-v20
```

Individual image targets: `make imagev20-2d` and `make imagev20-2hd`.
Images are build/images/fm11-cpm80-v20-{2d,2hd}.{d88,raw}.
The existing 8088 IPL binaries are reused; separate BIOS/system/server
binaries are in build/v20. RAW layout and diskdefs are unchanged.

## Emulator configuration

Use fm11-emulator with V20 BRKEM/CALLN/IRET support. Retain the usual ROM
and display settings. For 2D boot:

```ini
[DIPSW]
main_cpu = 8088
2D_FDD = true
2HD_FDD = false
HDD = false

[memory]
ram_kib = 128

[main_8088]
installed = true
cpu = v20
clock_hz = 8000000

[optional_cpu]
type = none

[floppy_2d]
drive0 = build/images/fm11-cpm80-v20-2d.d88
```

Use absolute image paths if running the emulator from another directory.
For 2HD boot, enable 2HD_FDD, disable 2D_FDD if desired, and mount
fm11-cpm80-v20-2hd.d88 as drive0 under [floppy_2hd].
Initial drives are A: and E: respectively.

## Execution and memory

Same 128 KiB minimum and 55 KiB TPA as the 8088+Z80 build.
The IPL loads the shared native server at 0400:0000. After cold disk
initialization it installs vector 40h -> 1000:F200 and vector 41h ->
the native I/O gateway, sets DS=1000h and executes BRKEM 40h.
CS and DS are both 1000h during 8080 execution. Guest SP maps to BP;
native SS:SP is independent (0400:2000 initially).
CP/M page zero and the mailbox remain in physical bank 1.

CPU_INIT is a RET; CPU_IOCALL is CALLN 41h (ED ED 41) followed by RET.
The native handler saves general and segment registers, establishes
DS=CS and ES=1000h, calls the shared server_dispatch, restores registers
and executes IRET. The mailbox returns results. No FD05 or FD2F accesses
are needed for CPU handoff/bank switching. Disk and console services
are polling; the backend masks the PIC to avoid stray guest IRQs.
RETEM is not a normal CP/M exit path; if invoked directly, the native
bootstrap stops. Native stack and interrupt vectors are outside guest RAM.

Native memory layout, track cache, warm boot, console and disk geometry
are inherited from the 8088+Z80 backend. No HDD support is added.

## Validation and limitations

make test-v20 checks binary sizes, BIOS cache vectors, gateway opcode
presence and both complete image layouts. It is not a boot test.
Boot and I/O on actual V20 hardware are not yet verified.
The emulator currently targets Intel 8080 instruction semantics where
V20 silicon behavior is unverified; undocumented opcodes, flags, and
timing may differ. Z80-only application instructions are not supported.
