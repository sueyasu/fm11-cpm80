# Experimental 8088 + Z80 target

Build with NASM, asm8080, Python and make: `make image8088` (or
`make image8088-2d`, `make image8088-2hd`). The normal make target
continues to build 6809 images. Both targets share CCP/BDOS and the common CBIOS, with a different
CPU_INIT bank selection and thus separate system62.bin files. The disk
filesystem layout and mailbox ABI remain identical.

The 8088 ROM enters 07C0:0000; the IPL relocates to 0100:0000 and reads
the 6 KiB server slot to physical 04000h. The server runs at 0400:0000
with private stack 0400:2000, cache at physical 06000h, and ES=1000h for
shared CP/M memory. Requires 128 KiB RAM.

With an 8088 main CPU, Z80 fixed windows 0000-3FFF and C000-FBFF map to
physical bank 1 even before FD2F is programmed. The native server loads
CP/M at physical 1DC00-1F5FF, installs JP F200h at physical 10000h,
and hands off via FD05h. CPU_INIT runs from the fixed upper window and
sets FD2F=1 before entering CCP, so all CP/M RAM is contiguous.
WBOOT reloads 22 sectors, cold boot 26. DMA pointers in the mailbox are
logical 16-bit offsets; all record copies use segment 1000h.

| Physical RAM | Purpose |
|---|---|
| 04000-057FF | native server including bounce buffer |
| 05800-05FFF | private stack |
| 06000-07FFF | write-back cache window 0 |
| 08000-09FFF | write-back cache window 1 |
| 10000-1FBFF | Z80 CP/M RAM |

The 8088 image uses `build/i8086/system62.bin`; the original 6809 image
still uses `build/cpm22/system62.bin`.

The FDC/8237 driver and local ANSI console derive from fm11-cpm86
commit 8f094f9708f06368b6eaa8be3b11fa446bd2e1dd (MIT). The ANSI translator now follows the 6809 parser: eight saturated
CSI parameters, matching SGR and cursor tracking, and transport CF errors.
`i8086/ansi_console.inc` is kept byte-identical to fm11-cpm86's
`src/cbios_ansi.inc`. Disk cache follows CP/M-86: two 8 KiB side-track windows, lazy fill,
32-bit valid/dirty maps, unused-first then round-robin replacement.
`track_cache.inc` adapts the CP/M-86 cache core; a geometry adapter in
`ioserver.asm` converts the unchanged CP/M-80 cylinder/record mailbox
to side-track/record coordinates. No HDD support.

Normal/unallocated WRITE updates cache only; directory WRITE flushes all
dirty data before the update and flushes again afterwards. Dirty eviction,
CACHE_SYNC and CACHE_RESET/WBOOT write pending sectors. Failed writes
retain unwritten dirty bits; no victim is reassigned on failed flush.
Call CACHE_RESET successfully before removing/replacing media; do not
hard-reset or exit the emulator with dirty data outstanding.
The existing minimum 128 KiB RAM and TPA are unchanged.

## Native server/backend boundary

`i8086/cpu_z80.inc` owns the entry at offset zero, private stack and
segment setup, the Z80 reset jump, silent boot failure handling,
and FD05 CPU hand-off. The common `i8086/ioserver.asm` owns cold
initialization, mailbox dispatch, disk reload, cache, and peripheral
services. The backend calls:

- `server_cold_init`: AL=boot drive (0 or 4), initializes the shared
  boot fields, loads 26 sectors and clears the disk workspace/mailbox.
  CF=1 on reload failure. It does not install CPU-specific entry code.
- `server_dispatch`: handles exactly one posted command and returns
  after setting STATUS and clearing CMD. CF mirrors STATUS (0 success,
  1 error). No CPU switch, reset jump or non-returning service loop.

Both require DS=CS (native server segment), ES=CPM_SEG, a private native
stack and disabled maskable interrupts. Both restore segment registers
and stack balance, leave DF clear and may clobber general registers
and other flags. The backend is responsible for saving/restoring any
guest CPU state. The Z80 backend calls dispatch after each FD05 return;
a future V20 backend can call the same routine from its native-mode
service gateway. BRKEM/CALLN/RETEM are not implemented here.

The emulator must support shared physical RAM, 8088/Z80 FD05 arbitration,
and the main-CPU-dependent Z80 fixed-window mapping. Use the patched
Windows v1.28 emulator for initial testing. The unmodified Linux port
may not yet implement these requirements. The pre-refactoring 8088+Z80 target was boot-tested with both 2D and
2HD media in the patched Windows v1.28 emulator.
